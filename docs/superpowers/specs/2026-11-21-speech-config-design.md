# ASR / TTS 重构与首次配置流程

## 目标

缺少 conf.yaml 时先生成带注释的默认配置并退出，不初始化 ASR、TTS、MCP 或下载模型。
用户手动选择引擎和填写参数后再次启动。已有 conf.yaml 不覆盖，保留当前 Sherpa ASR、Piper TTS 和角色配置。

## 方案选择

建议保留现有 character_config.asr_config / tts_config 及引擎名称：
使用显式注册表统一懒加载、构造参数适配与错误说明；配置层统一提供 engine_options()。
另一方案是拆分为独立引擎配置文件，但会要求用户跨文件编辑、迁移角色配置，不适合本次集中编辑 conf.yaml 的目标。
继续保留两套分支工厂虽然修改较少，但无法解决参数默认值被 None 覆盖、扩展方式不一致的问题。
此文档采用建议方案，待用户确认。

## 改动

1. 提供轻量的配置生成入口：仅复制中/英文模板，支持指定路径；文件已存在则拒绝覆盖。
2. 服务启动前先处理缺失配置：生成并明确提示手动配置，正常退出；将该检查放在重型服务导入和初始化之前。
3. ASR / TTS 工厂改为显式注册与按需导入，保留内置引擎、TTS 自定义引擎兼容行为。
4. 统一选中引擎的参数提取和校验；修正 ASR 校验名称不匹配，给出清晰的缺失配置与依赖错误。
5. 保留现有同步/异步接口及业务输出，提供商内部模型推理逻辑不在本次改写。
6. 同步两份默认模板的选项说明和命令文档；不把真实密钥写进模板。

## 验证

在临时目录验证缺失文件生成、再次运行不覆盖、中文注释和 YAML 有效性；
验证配置生成不导入模型 SDK；用替身测试工厂参数映射、默认值、未知引擎和缺失依赖；
校验现有 conf.yaml 及模板，运行现有测试与静态检查。

## 边界

不引入 LangChain 到语音推理模块，不切换当前启用的模型，不自动下载语音模型。
完成后重启正在运行的服务前，先确认配置仍可加载。
